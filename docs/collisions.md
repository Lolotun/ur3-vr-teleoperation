# Пол и самостолкновения UR3 в режиме RTDE

Проверки восстановлены поверх anti-windup и обработки остановочных статусов
Servo. Решатель KDL, gain, lookahead и локальный `.env` при этом не менялись.
Изменения из stash перенесены выборочно; сам stash сохранён.

## Модель и сцена

Общее описание в `rtde_real.launch.py` используется Servo, TF и collision guard:

- официальный `ur_description` для `ur3`, включая collision-меши звеньев;
- SRDF с официальными исключениями соседних и конструктивно исключённых пар;
- фиксированная точка `teleop_tcp` с настроенным TCP-смещением;
- сфера радиусом `0.01 м` вокруг TCP для проверки близости инструмента.

Сфера TCP не описывает корпус и пальцы Robotiq. Удерживаемый объект также не
добавляется автоматически. Для их проверки нужны отдельные collision-модели.
Если заводская калибровка не передана, остаётся номинальная кинематическая модель.

Пол — неподвижный box в `base_link`, верхняя поверхность на `Z=-0.01 м`.
Размеры `4×4×2 м`, центр по Z на метр ниже поверхности; box занимает пространство
вниз от пола. Только фиксированные `base_link` и `base_link_inertia` исключены
из столкновений с полом. Движущиеся звенья не освобождены от проверки.

Высота задаётся `RTDE_FLOOR_Z` в метрах или launch-аргументом `floor_z`.
Launch подставляет это значение поверх `floor.top_z` из YAML. По умолчанию везде
используется `-0.01`. Размеры пола, зазоры и шаг пути — в
[collision_scene.yaml](../ros/ros2_ws/src/teleop_core/config/collision_scene.yaml).

```yaml
check_self_collisions: true
scene_margin: 0.005  # 5 мм
self_margin: 0.003   # 3 мм
path_step: 0.02      # радианы
```

`check_self_collisions` применяется при формировании общей SRDF. Значение `false`
разрешает пары робот/робот, сохраняя проверку мира; сейчас выбрано `true`.

## Два слоя проверки

1. **MoveIt Servo** проверяет текущую сцену с частотой `50 Гц`. Начинает снижать
   скорость при зазоре меньше `1 см` до самого робота и `2 см` до объектов сцены.
2. **Collision guard** проверяет путь от свежего фактического Q до окончательной
   команды bridge после интегрирования и anti-windup. Проверка выполняется перед
   каждым `servoJ`, включая обычное удержание.

Второй слой нужен потому, что интегрированная команда опережает actual.
Проверки только текущего actual недостаточно для оценки этой команды.

Сервис `/teleop/check_state_validity` проверяет полноту/свежесть суставов,
суставные границы, допустимое опережение и интерполированный путь с максимальным
шагом `0.02 рад`. Геометрические проверки выполняет MoveIt/FCL.

Это дискретная проверка пути с запасами, не непрерывное доказательство
отсутствия столкновения и не замена защите контроллера UR. RGB/глубина камер
автоматически в сцену не поступают: неизвестные препятствия нужно моделировать.

## Остановка и выход из малого зазора

Настоящий контакт или пересечение блокируются. Если контакт отсутствует,
но положительный зазор уже меньше запаса, guard допускает удержание и движение
с измеримым увеличением хотя бы одного недостаточного зазора без уменьшения
другого. Проверяются промежуточные точки пути. Численный допуск `0.1 мкм` не
накапливается в разрешение постепенно ухудшать зазор.

Таким образом, положительный зазор `2.976 мм` при требуемых `3 мм` не блокирует
любой выход из положения. Движение глубже в опасную зону остаётся запрещено.
Servo при этом может продолжать сильно замедлять движение; его собственная
остановка по сингулярности или коллизии остаётся независимым ограничением.

При отказе сервиса, отсутствии guard или превышении таймаута `20 мс` команда
не отправляется. Bridge останавливает сессию, сбрасывает интегратор и требует
release/rearm; actual TCP и суставы продолжают поступать. Автоматического обхода
препятствия, изменения цели или отключения проверки нет.

Если Servo публикует остановочный статус `4`, дополнительно действует существующая
защёлка `SERVO_HALT_RELEASE_TO_REARM` со сбросом VR-привязки. Обычное замедление
по коллизии имеет статус `3` и само по себе не требует нового нажатия clutch.

## Применение и проверка

Пересборка требуется для нового C++-пакета `teleop_collision` и launch-конфигурации.
Работающий контейнер автоматически не перезапускается.

```bash
./scripts/run.sh down
./scripts/run.sh build
RTDE_ENABLE_MOTION=false RTDE_ENABLE_GRIPPER=false ./scripts/run.sh rtde
./scripts/run.sh shell
```

В контейнере:

```bash
source /opt/ros/humble/setup.bash
source /ws/install/setup.bash
ros2 param get /servo_node moveit_servo.check_collisions
ros2 topic echo /teleop/collision_status --qos-durability transient_local --once
```

Ожидается `check_collisions=true`. Статус guard отражает последнюю проверку
команды, а не непрерывную проверку idle-положения. До первого запроса он может
быть `WAITING_FOR_JOINT_STATES`, даже если обратная связь уже начала поступать.
Запросы начнутся при разрешённом upstream управлении, в том числе в preview.
Для проверки не нужно специально подводить реальный робот к полу или контакту:
геометрические контактные сценарии проверяются на поддельных состояниях.

Основные статусы `/teleop/collision_status`:

| Статус | Значение |
|---|---|
| `READY` | Последний проверенный путь допустим |
| `HOLDING_IN_PROXIMITY` | Удержание при положительном, но недостаточном зазоре |
| `RETREATING_FROM_PROXIMITY` | Разрешённый выход с увеличением зазора |
| `BLOCKED_SELF` | Самостолкновение или некорректный зазор |
| `BLOCKED_SCENE` | Контакт с полом/сценой или некорректный зазор |
| `BLOCKED_CLEARANCE...` | Путь нарушает запас либо не улучшает недостаточный зазор |
| `WAITING_FOR_FRESH_JOINT_STATES` | Не хватает полной свежей обратной связи |

JSONL-рекордер также сохраняет изменения `/teleop/collision_status`.
`command_step_ms` теперь включает ожидание collision guard; его нельзя напрямую
считать временем одного только вызова `servoJ`.

[anti-windup и разбор измерений](rtde-antiwindup-analysis.md).
